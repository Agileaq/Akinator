# Akinator 单页猜谜游戏 — 设计规格

日期：2026-10-01
状态：待评审

## 1. 目标与范围

实现一个类似 Akinator 的单页面猜谜游戏：玩家心里想一个真实或虚构的角色，程序通过一系列是/否式问题逐步缩小范围并最终猜出角色；猜不中时可以“教会”程序这个新角色，之后能被再次猜中。

范围：

- 纯前端静态单页应用，**零构建、零运行时依赖**，双击 `index.html` 即可游玩。
- 本地规则推理引擎（属性加权评分），完全离线。
- 内置约 50 个中外知名真实人物与虚构角色。
- 支持“也许是 / 也许不是 / 不知道”等模糊回答。
- 支持玩家教新角色，用 `localStorage` 持久化。
- 记录基础战绩（总局数、猜中数）。

非目标（本次不做）：

- 不接入任何大模型 API 或网络请求。
- 不做账号、云同步、后端服务。
- 不做图片资源；角色头像用 emoji 字符表示。
- 不做多语言（界面为简体中文）。
- 不做音效。

## 2. 技术选型

- 原生 HTML / CSS / JavaScript（ES Modules），无框架、无打包工具。
- 推理引擎为纯函数模块，不触碰 DOM，可用 Node 内置测试运行器 `node --test` 单测。
- `package.json` 仅声明 `npm test` 脚本，无第三方依赖。

## 3. 目录结构

```
Akinator/
├── index.html              页面骨架与挂载点
├── styles.css              神秘占卜风样式与动画
├── package.json            仅含 test 脚本，无依赖
├── js/
│   ├── data/
│   │   └── characters.js   属性表 + 内置角色库（ES Module 导出）
│   ├── engine.js           纯函数推理引擎（无 DOM）
│   ├── storage.js          localStorage 封装
│   └── app.js              状态机、DOM 渲染、游戏流程编排
└── tests/
    └── engine.test.js      引擎单元测试（node --test）
```

模块职责边界：

- `data/characters.js`：只导出静态数据（属性定义、角色数组）。不含逻辑。
- `engine.js`：输入候选集合与回答，输出下一问与猜测。纯函数、可独立测试。
- `storage.js`：读写/合并用户角色与战绩。对损坏数据做兜底。
- `app.js`：唯一操作 DOM 的模块，负责把引擎结果渲染出来并驱动状态机。

### 4.2 角色（characters）

```js
{
  id: "moana",          // 唯一字符串 id
  name: "莫阿娜",        // 展示名
  emoji: "🌊",          // 头像 emoji（数据内为 emoji 字符）
  attrs: {              // 仅列出已知属性；缺省视为未知
    isFictional: true,
    isHuman: true,
    isFemale: true,
    isCartoon: true,
    isAlive: true
  }
}
```

- 内置角色约 50 个（中外、真实与虚构混合），例如：牛顿、爱因斯坦、李白、孙悟空、林黛玉、哪吒、梅西、姚明、周杰伦、成龙、刘德华、马斯克、乔布斯、达芬奇、贝多芬、莫扎特、孔子、秦始皇、武则天、哈利·波特、赫敏、伏地魔、蜘蛛侠、钢铁侠、蝙蝠侠、超人、灭霸、米老鼠、唐老鸭、皮卡丘、哆啦A梦、柯南、鸣人、路飞、马里奥、塞尔达、林克、艾莎、莫阿娜、辛巴、海绵宝宝、史莱克、福尔摩斯、甘道夫、索伦、黑寡妇、神奇女侠、旺达、美队。
- 内置角色必须为全部 30 条属性赋显式 `true/false`：数据文件中只列举为 `true` 的属性，其余由构造器统一置 `false`（确定性优于未知，便于离线命中率调优）。`undefined`（未知）仅保留给玩家教会的新角色中“本轮未回答到”的属性。数据质量由测试与抽样校验保证。

### 4.3 用户角色（learned characters）

结构与内置角色相同，额外带 `learned: true` 与 `createdAt`。存于 `localStorage` 的 `akinator.userCharacters.v1`，值为数组。

### 4.4 战绩

`localStorage` 的 `akinator.stats.v1`：`{ games: number, guessed: number }`。

## 5. 推理算法（引擎规格）

引擎维护候选角色权重 `weights: Map<charId, number>`，初始各为 `1`。

### 5.1 回答类型与权重乘子

回答集合：`yes`（是）、`no`（否）、`probably`（也许是）、`probablyNot`（也许不是）、`unknown`（不知道）。

对某角色 `c` 与属性 `a`，令 `v = c.attrs[a]`：

| 回答 | v===true | v===false | v 未知 |
|------|----------|-----------|--------|
| yes | ×3.0 | ×0.3 | ×1.0 |
| no | ×0.3 | ×3.0 | ×1.0 |
| probably | ×1.6 | ×0.6 | ×1.0 |
| probablyNot | ×0.6 | ×1.6 | ×1.0 |
| unknown | ×1.0 | ×1.0 | ×1.0 |

每次更新后归一化：`weight[i] = weight[i] / max(weights)`，防止下溢并保持相对关系。记录已问过的属性，之后不再提问。

### 5.2 选题策略（信息增益近似）

在未问过、且至少对 2 个剩余权重非零候选“已知”的属性中，计算：

- `wYes` = 该属性为 true 的剩余候选权重之和
- `wNo` = 该属性为 false 的剩余候选权重之和

选择使 `min(wYes, wNo)` 最大的属性作为下一问（即把候选切得最接近对半）。并列时按属性 id 字典序稳定选择。

若无任何可用属性，或题目数达到上限 25，则停止提问，进入猜测。

### 5.3 猜测与停止条件

每次回答后判断：对权重归一化后占比 `share = weight[top] / sum(weights)`。

- 若 `share >= 0.85` 或已触发 5.2 的停止条件 → 猜 `top`。
- 猜错：将该角色权重置 0，重新归一化；若仍有至少 2 个权重 > 0 的候选且未到题量上限，继续提问；否则进入“放弃/学习”。
- 玩家主动点“都不是” → 直接进入学习。

### 5.4 学习流程

- 询问角色名称（文本输入，去首尾空格，非空校验）。
- 若与已有角色重名（含内置），提示“我好像已经认识它了”，不计为学习。
- 否则以本轮所有回答构造属性：`yes → true`、`no → false`、`probably / probablyNot / unknown → 未知`，写入用户角色（`learned: true`）。
- 学习后可继续下一局。

## 6. 游戏状态机

状态：`intro → asking → guessing → (wrong → asking) → learn → intro`，另有 `win`。

流程：

1. `intro`：开场动画与说明，“开始”按钮进入 `asking`。
2. `asking`：显示当前问题、五个回答按钮、以及随置信度变化的进度条。
3. `guessing`：显示猜测角色头像与名字，按钮“猜对了 / 再试试 / 都不是”。
4. “猜对了” → `win`（战绩 `guessed+1`），可再玩。
5. “再试试” → 剔除该角色回到 `asking`。
6. “都不是”或候选耗尽 → `learn`。
7. `learn`：输入角色名 → 保存 → 回到 `intro`（战绩 `games+1` 在每局开始时计一次）。

战绩：每开始一局 `games+1`；每次猜对 `guessed+1`。

## 7. 持久化

- 键：`akinator.userCharacters.v1`（数组）、`akinator.stats.v1`（对象）。
- 读取时校验 JSON 结构与字段类型，损坏或缺失则回退为空/零并覆盖。
- 启动时把内置角色与用户角色合并；同 id 或同名时以内置库为准（内置库不写回 localStorage）。
- 提供“清除我教过的角色”入口（放在 intro 或设置小按钮），二次确认后清空用户角色。

## 8. 视觉与交互

- 风格：深紫夜空渐变背景 + 金色描边与高光；点缀漂浮粒子/星点动画。
- 核心元素：魔法灯（开场）、水晶球或天平（提问/思考中）。
- 头像：圆形金色描边容器内显示角色 emoji。
- 过渡：问题切换淡入淡出，猜测时水晶球“思考”动效。
- 进度条：随 `share` 增长，颜色由紫转金。
- 响应式：移动端优先，按钮大而易点；桌面端居中卡片布局。
- 无障碍：按钮有可读文本，焦点样式可见，尊重 `prefers-reduced-motion` 时关闭粒子动画。

## 9. 测试策略

`engine.js` 为纯函数，用 `node --test` 覆盖：

1. 权重更新：给定回答与角色属性，权重乘子与归一化结果正确。
2. 选题：`min(wYes, wNo)` 最大化与稳定并列规则正确。
3. 停止与猜测：达到 0.85 与题量上限时返回 guess。
4. 猜错剔除：权重置 0 后重新归一化、候选不足时返回 giveUp。
5. 学习后可达：教会一个新角色后，重新跑同样回答序列时它能成为猜测结果。
6. 未知属性：`undefined` 属性在各类回答下按中性处理。

UI/视觉以手动验证为主，验收清单见下。

## 10. 验收标准

- 双击 `index.html` 可在浏览器直接运行，无控制台报错。
- 能完整走通：开始 → 多轮提问 → 猜中。
- 提供“也许是 / 也许不是 / 不知道”并影响权重。
- 猜不中时能输入并保存新角色，刷新页面后仍可被猜中。
- 战绩计数正确并能跨刷新保留。
- 关键推理路径（`engine.js`）在 `npm test` 下全部通过。
- 移动端窄屏布局可用，无横向滚动。

## 11. 风险与权衡

- 内置角色属性表的数据质量直接决定命中率。内置数据采用显式布尔（无未知），故 `undefined` 的中性路径只由玩家教会的新角色触发；需对内置数据做抽样人工校验。
- 归一化采用按最大值缩放而非求和，保留相对大小；`share` 计算时再取真实总和比例。
- 属性集合固定，玩家教的新角色也只能落在这 30 条属性上；这是离线方案的固有限制，可接受。
- 纯前端学习仅存于本机浏览器，换设备/清缓存会丢失，属预期行为。
